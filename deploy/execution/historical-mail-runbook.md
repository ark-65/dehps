# Independent historical-learning notification release

Engineering842 adds a separate observer-domain Goal. It does not alter the
historical learning plan, sufficient statistics, algorithms, formal P3, V11,
the frozen prospective research contract, or existing mail delivery records.

The six phases per issue are seal, pre-report, pre-replay, result, post-report,
post-replay. The common Coordinator, dependency resolver, Ready Queue, PostgreSQL
immutable commit/registration APIs and deterministic replay are mandatory.
Mail consumes registered replay artifacts; replay itself cannot send or train.
The authenticated publisher checks producer and observer registration, the
entire consumed label prefix against the audited source, and the existing
registered formal checkpoint's issue/calendar. It signs separate inputs only.

Use a new exact Operator request after accepted Engineering. Bind committed
source, fixed worker image/release/plan, recipient digest, original historical
expiry, source identities, all installed paths and rollback. No production
strategy promotion is implied. Reuse the registered observer Operator identity;
use genuine mapped ark authentication for ephemeral existing Engineering and
Reviewer login sessions when admitting the new plan. No identity/grant/schema
changes or changes to old approvals are needed. Disable the temporary logins
and erase their transient authentication secrets after each session.

Install a separate root-protected host source/config/package and observer-owned
runtime. The worker runs the fixed image without IP networking, SMTP credentials
or a Docker socket. Its non-root launcher uses only the existing observer Unix
database socket and scoped Operator credential. The root host service has an
explicit writable path allowlist, one BLAS thread, a bounded timeout, a shared
notification lock, the existing 18–22 formal guard and private failure evidence.
Existing historical and formal services are not restarted or changed.

Install two new timers: pre at17:00 Tue/Thu/Sun Asia/Shanghai; post checks every
15minutes after the previous cycle has finished. Post polling also prepares a
future seal as soon as the immediately preceding learned/observed checkpoint
and formal calendar are available. Before timer enablement, `prepare` creates
registered readable previews and `replay` verifies them without sending mail.
Only scheduled `pre`/`post` actions perform the explicitly authorized delivery.
Expiry stops new inputs, commits and delivery; it never extends itself.

The independent ledger deduplicates by issue/kind/recipient. A changed envelope
cannot create a second send. A process interruption or ambiguous SMTP response
leaves sending/uncertain state, blocks automatic resend and requires recorded
transport reconciliation. There is no claim of transactional SMTP exactly-once.
If a pre-draw seal is missing after the draw, register a gap and mail only the
actual result with the explicit gap. Never manufacture past candidates or hits.

Rollback stops and disables only the two new timers/services. Keep all admitted
plans, successful/failed artifacts, previews and delivery evidence. Existing
30-day learning admission and history timers retain their previous expiry.
Before/after acceptance covers the exact current formal issue's seal, source,
registration, replay, readable report, ledger and timers. Future scheduled mail
is PENDING_DELIVERY. Acceptance does not authorize a test email.
