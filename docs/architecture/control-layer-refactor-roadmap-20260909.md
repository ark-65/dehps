# DEHPS 控制层重构目标与 Codex Roadmap

日期：2026-09-09  
源码基线：`ark-65/dehps@ac0ef7832c6f13c7500b3f7d67731420b575c0f4`  
用途：交给 Codex 执行的重构范围、迁移顺序和验收合同草案。  
本轮交付：源码分析与实施计划；未修改仓库、部署服务、批准 Request 或运行模型。

## 1. 决定：保留科学资产，重构运行控制层

**不建议全项目重写。建议对权限、执行、恢复、发布、状态/报告消费及工程流程进行结构性重构。**

这是一次涉及多个模块的重构，不能再限制成“只改五个文件、修一个异常”。也没有证据支持重新开发数据库全部业务表、采集器、预测算法、API 和前端。

初步按 R0–R5 **8–12 个可审查 PR** 组织。这个数字是拆分预算，不是工作量测量或完成保证；R0 核对实际调用者后调整。当前无法负责任地给出精确代码比例、token 数或工期。

**总目标：**

> 将 DEHPS 改造成可独立开发、可确定性验证、可中断恢复、可受控发布的预测分析系统。正式预测保持科学合同和证据连续性；误差分析与模型实验使用明确的输入和独立副作用边界。新增实验不需要修改公共执行器，不需要重启正式 P3，不等待旧 V11 日报恢复。批准必须来自真实授权主体。测试成功、部署成功和预测改进分别给出结论。

本轮重构的直接成果是稳定迭代能力，不承诺中奖率、预测优势或收益改善。

## 2. 为什么是这个范围

本轮重新读取了 GitHub 固定提交的完整文件树，并检查控制面、仓储、学习模块、审批入口、API 状态读取及 CI。文件树共 1,742 个文件，其中 worker 下 `dehps/` 有 521 个 Python 文件。不是逐文件完整安全审计。

| 已核实的代码事实 | 对重构范围的影响 |
| --- | --- |
| `research_os/supervisor.py` 有 34,761 行；直接出现 67 个不同的信息论实验模块 import 来源 | 必须把通用执行机制与实验注册、历史恢复和状态投影分开；机械切文件不够 |
| `research_os/repository.py` 有 4,912 行，包含历史恢复 builder、特定 Request ID 和 digest | 仓储层也要抽出历史兼容策略，不能只处理 supervisor |
| 观察服务覆盖了 `state_path`，却继承另一条写正式状态文件的 `_write_lane_status` 路径 | 所有可写位置都需要显式归属，同时用进程权限约束 |
| 生命周期接口接受调用者传入 reviewer/executor 标识；已读独立性检查主要比较字符串 | 身份认证、授权判断和执行权限必须分离，不能把标签当独立审查 |
| `learning_v1_runtime.source_identity()` 将整个 `dehps/**/*.py` 纳入冻结身份；当前涉及 521 个 Python 文件 | 修改无关模块也可能让实验恢复失败；需要固定 release 和明确依赖身份 |
| 学习 runner 读取生产 `.env`，沿用连接参数创建实验数据库 | 改库名和事务 READ ONLY 不能替代独立凭据；实验不应默认取得生产凭据 |
| `LearningSupervisor` 仍修改基类全局 namespace，并直接调用私有完成加载器 | 已有学习计算可复用，但运行接入需要迁移 |
| 观察测试替换了真实原子提交；worker CI 文件未配置 PostgreSQL service | 必须增加真实持久化与重启验收；不能用测试总数代替该路径覆盖 |

## 3. 保留、迁移与退出

| 对象 | 本轮处理 | 边界 |
| --- | --- | --- |
| 历史开奖、冻结合同、原始预测、模型 checkpoint、结算及失败证据 | 保留 | 不改历史字节、digest、事件顺序和审批来源 |
| 既有 Formal P3 科学计算和前向合同 | 固定版本继续服务 | 不修改模型、特征、阈值、候选语义、蓝球策略或证据口径 |
| 采集、合法组合生成、指标、样本时间边界和有效纯计算 | 优先复用 | 迁移前建立行为基线；不能仅因能复用便假定无缺陷 |
| `error_learning.py`、`learning_v1.py` 的分析/学习计算 | 保留计算，抽离运行依赖 | 不把正式通知/运行模块整体带入新的计算核心 |
| supervisor、repository 的执行/提交/恢复部分 | 重点重构 | 统一策略入口，删除新路径中的全局 monkey patch |
| 状态、报告、邮件执行机制 | 分离职责、保留内容合同 | 计算完成不依赖 SMTP 成功；发送未知状态不能自动重发 |
| 审批与执行入口 | 重构信任边界 | 真实身份，不允许执行者自称独立 Reviewer |
| API 和前端 | 适配受影响的状态来源和接口 | 不是 UI 全面重写；不确定或过期状态不得伪装成功 |
| V11、特定事故修复脚本 | 退出新任务可达路径，保留归档 | 不恢复旧日报，不创建相关 V11 Request，不删历史证据 |
| 其他庞大旧训练/监控模块 | 盘点实际调用，再迁移必要部分 | 文件大不是立即重写理由，未使用部分不成为本轮默认依赖 |
| 项目工程规则和 CI | 与上述边界同步调整 | 项目规则变更必须真实获准，不能伪造审批或绕过平台限制 |

正式 P3 冻结期的设计终态可以是：**旧计算运行在专用固定 release；新观察和实验使用新运行边界，通过合法 artifact 接口读它。** 这是一项明确兼容安排，不宣称 P3 已迁入新执行器。

P3 执行器本身的迁移，只有在科学合同允许且工程等价验证通过后才能进行；否则保留该安排，待合同允许时另列迁移任务。它不能继续阻塞独立模型研发。

## 4. 目标结构：少量明确接口，不再创建一个新 Research OS

建议保留同一仓库、Python worker、PostgreSQL 和现有部署方式，只提取必要边界。目录名可由实施时确定；不以固定类名或文件数验收。

| 边界 | 应负责什么 | 不应承担什么 |
| --- | --- | --- |
| 计算与领域模块 | 输入数据、固定配置 → 模型、候选、评分、诊断结果 | 审批、systemd、SMTP、生产数据库初始化 |
| 运行上下文 | 明确 code/artifact/state/status 根目录、读写权限、release 和任务归属 | 按未知 control plane 默认选择正式路径 |
| 执行存储与发布 | 任务尝试、持久化结果、唯一提交记录、checkpoint、并发互斥 | 某个历史期号的专用补丁、根据显示状态推定事实 |
| 版本化验证策略 | 同一组规则用于提交前、提交后、replay 和下游消费 | 各处另写一套恢复判定、异常捕获后绕过验证 |
| 报告与投递 | 消费合法完成结果，生成自有报告、outbox 和投递记录 | 重训、改预测、重写正式状态或把未确认邮件标成 SENT |
| 授权与发布 | 校验可信身份和具体发布对象；运行固定 release | 让任务通过字符串参数自行切换 Reviewer/Operator 身份 |

依赖方向应是：业务模块实现公共接口，入口负责组装。通用执行核心不能反向导入 V11、P3 事故修复脚本或某个期号的实验实现。

现有纯 `ResearchOSControlPlane`、resolver、ready queue 和稳定数据结构优先复用。新核心不用重建所有历史调度功能；先支持一个完整的观察任务和一个完整的实验任务。

## 5. Roadmap

R0–R5 是本轮工程重构。R6 是重构后衔接的科学实验目标，单独判定，不把“模型必须更准”写成工程关单条件。

### R0：建立基线、迁移清单和一次完整的工程范围

规划：1 个 PR。

工作：
1. 固定实际 main 和在役 release，记录工作树状态；用户未提交修改保留，使用独立工作区。
2. 列出实际启用的服务、timer、入口、数据库角色、状态写入者、artifact 消费者和 source 依赖。
3. 对 Execution 656 及观察状态文件做必要的只读核查。保留原始记录；发现错误时用后续审计事实说明，不篡改旧批准记录。
4. 为下列内容做基线：冻结科学输出、历史 artifact 可读性、当前接口响应、关键任务完成与恢复行为、相关 CI 失败。
5. 写一个架构决策和迁移清单，每个活动入口明确“本轮迁移 / 固定旧 release / 已停用”。
6. 把本轮所需项目规则修订集中提出并真实确认：离线研发完成、发布就绪、部署、投递验收、科学有效性分别记录。独立研发不依赖旧 V11 缺口。
7. 既有同一范围内的普通代码修复和测试迭代使用持续有效的工程授权；不因每个异常自动创建新 Request。权限撤销或范围扩张仍需合法处理。

退出条件：
- 范围清楚，没有把“所有历史事故必须修好”作为下一阶段前提。
- 生产事实有证据的写已确认，没有访问的写未知。
- 存在有效工程授权才进入代码修改。没有合法审批条件时，不得制造身份或自批；可以交付完整可审查材料。
- 未解决的现场疑点阻止相关生产切换，不必阻止已有授权下的独立离线开发。

### R1：先落实写入隔离与真实身份

规划：2 个 PR，状态/资源与身份分别审查。

工作：
1. 显式配置所有状态、日志、artifact、锁和 outbox 路径；校验归属、冲突和路径逃逸。
2. 检查 waiting、running、completed、failed、启动及异常分支的全部写入，不仅是 `state_path`。
3. 服务仅可写自己的目录。观察/实验使用独立凭据；读取正式数据通过允许的只读视图或快照，不读取未开放汇总。
4. 取消实验入口默认加载生产凭据、使用生产账号创建数据库的设计。测试库和实验库由合法配置提供。
5. 审查与执行身份来自可信会话或独立认证入口；调用者传入的 label 仅作显示，不能决定权限。
6. 批准绑定请求内容和具体发布身份；开始执行时再次验证批准有效及执行者与审查者分离。
7. 校验数据库直接写入和部署通道，避免 MCP 入口修好了、同一凭据仍能绕过它。
8. 用户同意须记录为真实用户同意；不能重标成一次独立技术复核。

退出条件：
- 双 control plane 的真实入口测试证明互不写状态或业务记录；正式 sentinel 的内容及修改时间不变。
- 运行账号即使代码误选正式路径/数据库，也被权限拒绝。
- 同一认证主体更换 reviewer_id 仍不能审批自己；先审批后执行也不能绕过分离。
- 可信身份基础设施未就绪时，受影响发布保持不可用；不伪造“安全已完成”。

### R2：统一执行、提交和恢复语义

规划：2–3 个 PR。

工作：
1. 从现有控制层抽出最小执行接口、版本化验证策略与持久化存储接口。
2. 区分任务定义、尝试记录、运行版本和已提交结果；失败尝试不被改写成成功。
3. 明确定义业务唯一键、重复调用规则、并发 claim 和过期执行者不能继续提交的约束。
4. 已提交任务从持久化结果验证并继续；未提交任务按冻结规则从 checkpoint 恢复或重做未完成计算。
5. 同一验证策略覆盖提交前、readback、replay 和下游读取；保留每个历史版本的原验证语义。
6. 把状态文件作为可重建投影。显示写入失败不反转已经提交的计算事实；必要证据损坏仍阻断对应下游。
7. 数据库事务不自动等于“数据库与文件系统跨介质原子”。实现明确发布协议：准备及验证不可变文件，持久化引用/完成事实；崩溃后能够识别未引用文件、已提交引用和证据缺失。
8. 若原 schema 足够就复用；确有必要时使用增量 migration、新表/字段和兼容读取。不得为避免 schema 变更把状态塞进事故专用补丁。
9. 历史特殊恢复保留在只读版本适配器或归档 release；新通用核心不硬编码旧 Request ID、某期 manifest 或某事故 digest。

退出条件：
- 使用相同 migrations 的真实 PostgreSQL，fixture 具有完整外键父记录。
- 真实提交与重启测试覆盖提交前、commit 后未收到确认、验证失败、replay 前后和下游中断。
- 已提交计算的重复 resume 不重训、不重复注册、不覆盖 artifact；未完成计算的合法恢复明确计入 attempt。
- 并发竞争不会产生两个业务成功结果。
- 不能 mock 掉待验收的 rebind、事务或状态迁移；传输边界可以使用假 SMTP。
- 重复业务操作无重复副作用；允许有明确去重策略的新诊断日志，不要求整个数据库和文件树永久字节不变。
- 新路径不临时替换 supervisor 全局函数。

### R3：固定发布版本，拆开代码与运行数据

规划：1–2 个 PR。

工作：
1. 分离开发工作区、固定 release、运行状态及不可变 artifact 根目录。
2. 每个 release 固定代码、依赖环境、入口和配置，生产入口不能随开发切分支或脏工作树变化。
3. 可以先把原生产路径作为专用固定检出保留，研发移到独立工作区；无需一次搬走全部历史目录。
4. 分开记录科学合同身份、运行实现身份及 artifact schema 版本；三者都校验，不能简单删掉代码校验。
5. 新实验通过固定 release 表达真实依赖闭包。保留整个 release 的完整身份；不要要求历史实验继续追随开发目录里全部 521 个 Python 文件。
6. 历史实验使用归档代码/环境 replay；不修改原 source 合同去迎合新代码。
7. 有计划地适配 API 和监控消费者，显式指定各自状态来源；路径缺失、身份不符或过期必须明确显示。
8. 制作发布与回退材料。回退切换代码/配置，不倒退删除数据库事实；新 schema 必须有兼容或前向修复方案。

退出条件：
- 修改或切换开发分支不改变在役 release 的源码身份和输出。
- 历史 artifact 可以由其对应版本验证。
- 新实验可在无生产凭据的环境中运行；release 依赖变化不会被默默忽略。
- API 读取正确归属，不借旧成功状态掩盖新任务失败。
- 在隔离环境完成发布与回退演练。

### R4：迁移两条完整路径，证明研发真的解耦

规划：1–2 个 PR。

路径 A：合法已开放预测/结算 → 冻结决策记录 → 全部 100 注诊断 → 样本与报告 → replay。

路径 B：固定数据快照和实验合同 → 有限训练/评估 → checkpoint → 差异与基线报告 → replay。

工作：
1. 复用现有 `error_learning` 和 `learning_v1` 计算，通过新接口运行。
2. 移除迁移路径对旧 supervisor 私有函数、全局 registry 和生产 `.env` 的依赖。
3. 使用真实 PostgreSQL、真实文件及不同进程重启进行集成验证。
4. 用已固定的历史输入做新旧对照；历史重建不得冒充当期开奖前证据。
5. 预测排序、候选语义、概率、蓝球规则和诊断内容按冻结要求保持一致。时间戳、运行 ID、新版本 envelope 可以合法不同，必须单独解释；不能宣称所有新旧 digest 必须相同。
6. 科学计算不得因为迁移重新调参。把运行耗时、测试结果与科学指标分开。

退出条件：
- 两条路径在隔离环境独立完成并可恢复，不调用正式可写接口。
- 已有诊断、概率模型和历史实验结果能复用。
- 加入一个仅用于架构验收的确定性测试能力，只需自己的模块、配置和测试；不修改执行核心，不新增生产邮件依赖。
- R4 本身只验证计算和集成；不启动未经授权的新科学搜索。

### R5：受控切换和移除双写入口

规划：1–2 个 PR。

工作：
1. 列明待发布 commit/release、受影响服务、准确命令、配置差异、数据写入范围和回退步骤，形成具体发布包。

### R6：回到预测分析与新模型训练

这是下一个科学里程碑，不是扩大当前工程重构范围。

已有资产：仓库首轮学习报告记载完成 2,599 期历史逐期评估，结论为“证据不足”：收缩模型相对旧模型的 log-loss 改善，没有证明优于均匀基线，也没有证明收益改善。本轮未重新计算该报告，不能把记录等同新的独立证据。

依据：[首轮学习结果](https://github.com/ark-65/dehps/blob/ac0ef7832c6f13c7500b3f7d67731420b575c0f4/docs/experiments/2026-09-05-prediction-learning-v1-results.md)。

下一轮目标应是一个有限、预先定义的实验：
1. 保留每期全部 100 注的候选生成、过滤、评分、排序和选择证据。
2. 对每注列出遗漏/多选号码；例如 7 换成 2 时，读取开奖前模型的概率、分数差、约束和排名变化。
3. 区分“没有生成该组合”“生成后被过滤”“评分偏低”“选票策略未选”“蓝球不符”，不能把所有失败都归给模型概率。
4. 完整红蓝标签在合法开奖后入样；预测输入严格来自目标期之前可用的数据。事后标签和诊断不能倒灌为当期特征。
5. 诊断说明程序为何选择 7，不声称发现彩票开奖为何开 2 的因果规律。
6. 新合同固定一个主要假设、有限候选、seed、时间切分、预算、主指标、对照、multiplicity 与停止规则。具体算法须研究定义获准后决定。
7. 对现有模型和合法随机/均匀基线分别比较；概率误差、候选覆盖、Top-100 命中和模拟收益分别报告。
8. 所有历史已使用的结果标为探索性；不能把同一历史窗口重跑包装成新的确认性检验。
9. 没有改进也是有效实验结论；不自动开始第二轮，不自动 Promotion。
10. 重训练由程序消费新数据或合同内未完成任务，不让 LLM 全天循环改代码。

## 7. 防止再次无限迭代的工作方式

1. **固定有限目标。** R0 明确范围后，普通错误在同一授权工程范围内持续修复；不把每个 bug 升级为新工程项目。
2. **授权按动作边界。** 代码实现、独立审查和生产执行分别真实授权；不允许通过换名字完成角色切换。撤销的 V11 权限不被本计划恢复。
3. **完成按事实分层。** 每阶段报告代码与离线验收、发布、业务周期和科学结论。不要用唯一 `INTEGRATION_PENDING` 抹掉已经完成的独立工作。
4. **依赖按实际关系。** 旧日报、P4–P6 或未开放累计指标不成为新离线实验默认前置条件。
5. **不重复无效检查。** 同一错误没有新代码或新证据时不再重复跑相同命令。先定位，再做相关回归。
6. **保存一个持续更新的检查点。** 记录当前 commit、阶段、已通过证据、唯一剩余问题及下一动作。会话恢复先读检查点和增量 diff，不重讲全部历史。
7. **程序工作由程序完成。** 训练、checkpoint、定时等待和日志统计不用持续 LLM 对话驱动。无新任务时停止或等待，不机械重训。
8. **达到验收便停止扩展。** 不主动加入新的模型族、通用插件框架、调度中间件或可选平台改造。
9. **越界只停受影响动作。** 范围新增、授权失效、真实身份不明、生产漂移或必须修改冻结合同，停止对应写入/发布并报告；不擅自绕过，也不把所有离线工作一并宣布永远无法继续。
