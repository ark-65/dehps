# Feature Contract v1 Specification

## Status and scope

This document freezes `feature.v1.0.0`, the first normative contract for DEHPS scoring features.

Primary goal:

> Freeze feature meaning before Feature ABI, Runtime Envelope migration, or any GPU/SIMD backend work.

This round defines the feature component manifest, component order, weight-field mapping, dependencies, dtype policy, finite-value policy, formulas, and a golden vector. It does not create a Feature ABI package and does not change runtime scoring.

Non-goals:

- no Feature ABI layout;
- no Kernel or Numba change;
- no scoring formula change;
- no weight or search-space change;
- no production prediction, pending-run, or database mutation.

## Contract rule

Feature is a function of Window and Candidate:

```text
Feature = F(WindowArtifact, CandidateABIPackage)
```

It is not a function of Candidate alone. A feature value is meaningful only when the history snapshot, window boundary, candidate identity, and formula contract are all fixed.

## Component manifest

`feature.v1.0.0` freezes a 32-component vector:

```text
shape = [N, 32]
dtype = float64
order = component index ascending
NaN/Inf = rejected
```

Each component has:

- `index`;
- `feature_id`;
- `weight_field`;
- `dtype`;
- `shape`;
- `unit`;
- `value_contract`;
- `dependencies`;
- `formula`;
- `missing_policy`.

The component manifest digest is `FEATURE_COMPONENT_MANIFEST_DIGEST` in `dehps.input_contracts.feature_contract`.

## Golden vector

The contract includes a golden vector fixture:

- history issues: `2026001` through `2026004`;
- candidate: `[3, 8, 12, 18, 25, 33]`;
- output shape: `[1, 32]`;
- dtype: `float64`;
- expected values: stored in `FEATURE_GOLDEN_SUITE["golden_vector"]["values"]`.

The golden vector is generated by the current reference `component_tile` implementation and is used as the first cross-implementation oracle. Future Feature ABI, Numba, SIMD, CUDA, OpenCL, or Rust feature compilers must reproduce it before promotion.

## Runtime boundary

This is a contract specification round only.

Allowed now:

- publish the Feature Contract and component manifest;
- verify manifest shape/order/dtype/finite policy;
- compare the reference implementation against the golden vector.

Not allowed in this round:

- passing Feature Manifest into Kernel;
- compiling Feature ABI buffers;
- replacing `component_tile`;
- changing score/rank outputs;
- changing production prediction identity.

## Migration order

The next feature rounds should remain staged:

1. Feature Compiler reference implementation.
2. Feature ABI v1 specification.
3. Feature ABI Runtime Migration.
4. Runtime Envelope v1 propagation.
5. Unified Runtime Verifier.
